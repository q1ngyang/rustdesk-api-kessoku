# RustDesk API Kessoku v3.0.5 数据库迁移与回退

v3.0.5 继续使用数据库版本 `309`，启动时通过常规 AutoMigrate 增量加入审计身份和平台
设置字段。变更以新增字段为主，但生产升级仍必须准备完整恢复集合。

`v3.0.4` 候选从未公开发布，因此不存在受支持的 v3.0.4 运行版本升级路径；现有部署应从
v3.0.3 或文档中列明的更早正式版本升级。

## 升级前

请备份并实际验证能够恢复：

- 完整数据库；
- TOTP 加密密钥和访问令牌签名密钥；
- 媒体目录、配置、环境变量文件和当前镜像 digest；
- 反向代理配置、TLS 证书及 Starry PKI。

最终备份前停止全部 Kessoku 写入实例。迁移期间不得让 v3.0.3 与 v3.0.5 同时写入同一
数据库。

## 升级

1. 先在隔离环境恢复备份并完成升级演练。
2. 只启动一个 v3.0.5 实例，等待数据库结构更新完成。
3. 确认原有用户、设备、Token 和审计记录仍在，数据库序号没有被重新生成。
4. 验证设备上报、连接/文件审计、受控端完整路径、服务端控制日志来源、服务配置二维码和
   品牌默认内容。
5. 检查“平台设置”；记录保留天数为 `0` 时不自动清理，确认合规保留周期后再主动启用。
6. 在生产环境重复“停止写入—完整备份—单实例升级”流程，并固定已验证的 v3.0.5 镜像
   digest。

## 回退

不要让 v3.0.3 或更旧程序读取已经由 v3.0.5 打开的数据库。停止全部写入实例，并同时恢复
升级前匹配的数据库、TOTP 密钥、媒体目录、配置、签名密钥、PKI 和旧镜像 digest。
