# Kessoku v3.0.4

v3.0.4 是 Kessoku v3 支持版本的稳定性与运维更新，重点改善设备发现、审计记录、服务
配置、日志容量控制和日常管理体验。

## 主要更新

- 修复原生客户端设备发现与上报合并，自动发现和手动添加的设备均可刷新主机名、用户名、
  UUID、操作系统、CPU、内存和版本；查询前会统一清理 RustDesk ID 中的空格。
- 新增对所有用户开放的服务信息卡片，展示实际 ID 服务器、API 服务器、公钥、可复制的
  客户端配置和二维码；中继节点信息仍可查看，但不会引导用户误填只能原生连接的节点地址。
- 修复连接与文件审计的写入、归属、两端身份、受控端完整路径、UUID 和倒序排列。Token、
  登录、连接、文件页面统一显示数据库持久序号，删除后的序号缺口会保留，不再按页面重排。
- Token、登录、连接、文件和服务端控制审计新增日期筛选。平台设置可配置网页/原生客户端
  登录有效期及记录保留天数；所有保留天数默认 `0`，表示不自动清理。
- 服务端控制新增 Kessoku、Starry 和 Relay 日志来源及下载；开启可写控制模式后可受保护地
  调整运行时日志级别。示例配置默认启用日志轮转，并限制单文件大小和保留数量。
- 新增当前管理实例名称设置，并补充状态、协议、认证、能力与控制模式的零基础说明。
- 修复旧版 v3 数据库升级后品牌默认值为空的问题，并继续完善明暗主题素材、上传、关于服务、
  响应式布局、表格密度、用户名、日期和多语言帮助文本。
- 移除无实际数据来源的“分享记录”后台入口；地址簿集合和分享规则功能仍然保留。

## 兼容性与升级提示

- 数据库版本仍为 `309`。启动时 AutoMigrate 会增量加入审计身份和平台设置字段，已有记录
  的数据库序号不会被重新生成。
- 升级前备份数据库、TOTP 密钥、媒体目录、配置、签名密钥和 PKI；迁移期间只启动一个
  v3.0.4 写入实例。
- 已有部署的记录保留天数初始化为 `0`，管理员主动设置前不会自动删除历史记录。
- 正式支持的制品平台仍为 `linux/amd64`，Go 模块路径仍为
  `github.com/q1ngyang/rustdesk-api-kessoku/v3`。
- 不要对已迁移数据库原地降级；应停止全部写入实例并恢复升级前完整且匹配的备份集合。
