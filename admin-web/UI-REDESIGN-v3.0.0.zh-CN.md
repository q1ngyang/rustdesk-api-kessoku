# RustDesk API Kessoku v3.0.0 界面重构说明

## 目标与边界

v3.0.0 管理界面直接以本仓库 v2.8.3 的 `admin-web/` 为上游继续开发，不创建独立前端仓库，也不从 `lejianwen/rustdesk-api-web` 覆盖或回填源码。这样可以保留 Kessoku 已完成的接口适配、安全约束与内置发布流程，避免前后端版本错配。

本轮范围是登录、注册、个人工作区、管理后台、Server Control 与通用交互组件的视觉和布局重构，并包含已确认的企业管理员层级。以下技术边界明确不变：

- Vue 3、Vite、Element Plus、Pinia 与现有 API 封装；
- 动态路由仍由后端 `route_names` 生成，界面不自行推导接口权限；
- Server Control 的类型化 DTO、ETag、plan/apply、幂等键与审计流程；
- 内置 Web Client 的连接授权、来源校验和内存交付边界；
- 部署配置和 RustDesk/Starry 协议。

权限是本轮唯一有意扩展的后端边界：数据库版本升级到 302，原 `is_admin=true` 管理员无损迁移为 `super_admin`，新增 `admin` 角色与资源范围表。除角色和范围接口外，不重写既有业务模型。

## 设计方向

整体采用低饱和浅灰背景、白色内容面板、柔和边框和轻阴影，主色使用偏蓝紫色。信息密度保持管理工具所需水平，通过更清晰的标题层级、卡片分组、状态色和留白降低阅读负担，而不是删减功能。

品牌名统一为 **RustDesk API KESSOKU**。页面左上角、favicon 和通用项目标识使用仓库内置的 StarryLinks icon，并与 `RustDesk API KESSOKU` 或 `KESSOKU` 文字搭配；完整 StarryLinks Logo 只在登录页、STARRY 节点控制页和关于页出现，注册、OAuth、异常页及普通后台业务页不展示完整 Logo，避免混淆项目主体。浅色界面只显示 `light` 资产，夜间模式只显示 `dark` 资产，favicon 也跟随主题即时切换。

装饰中继续使用两层克制的隐喻：个人概览卡片左侧保留紧邻竖排的蓝、黄小方块（蓝色在上、黄色在下）；蓝、黄、红、粉不组成生硬的并排色条，而是分散承担功能语义——蓝色用于主操作与设备，黄色用于地址簿与需关注信息，红色只用于危险操作或异常，粉色用于身份、共享和连接提示。它们首先服务于识别、状态表达与视觉层级；熟悉相关作品的用户可以识别彩蛋，但页面不出现角色、台词、乐队图案或其他直白引用。

## 相比原界面的变化

| 区域 | 原界面 | v3.0.0 | 调整原因 |
| --- | --- | --- | --- |
| 登录与注册 | 单一深色表单，品牌和功能说明较弱 | 桌面双栏品牌叙事 + 聚焦表单；手机收敛为单卡片 | 提升第一印象，并让认证方式、验证码和注册入口更易理解 |
| 全局导航 | 固定侧栏，窄屏适配有限 | 桌面完整侧栏、平板默认收起且可展开、手机抽屉 + 底部快捷导航 | 保持平板功能完整，并缩短手机高频路径 |
| 顶栏与页签 | 控件分散，页面定位感较弱 | 固定半透明顶栏、当前页面标题、可关闭历史页签、主题和语言集中 | 强化当前位置与跨页面切换效率 |
| 工作区首页 | 以账户资料为主 | 管理员展示用户/设备/用户组统计，普通用户展示个人设备/地址簿/分享；补充安全与快捷入口 | 首页直接回答“当前状态”和“下一步做什么” |
| 列表页 | 筛选、表格与分页视觉层级弱 | 统一卡片、输入控件、表头、状态标签、按钮与分页样式 | 降低不同业务页面之间的学习成本 |
| 手机表格 | 固定宽操作列可能遮挡数据 | 小屏取消操作列固定定位，保留完整横向滚动 | 不隐藏能力，确保每项操作仍可到达 |
| 表单与弹窗 | 固定宽度和横向标签较多 | 手机单列标签、近全屏弹窗、底部安全区、按钮自适应 | 提升触控命中率，避免键盘弹出后内容不可达 |
| Server Control | 功能完整但更偏工程页 | 增加页头和实例状态；卡片、页签、描述列表、工具栏及 YAML 编辑器响应式重排 | 在不改变安全工作流的前提下提升可读性与移动可操作性 |
| OAuth/异常页 | 独立旧深色风格或纯文本 | 与登录页统一的品牌操作卡和明确状态反馈 | 让认证流程在弹窗、小屏和异常场景中保持一致 |
| 深色模式 | 组件覆盖不一致 | 由统一设计令牌驱动的浅色/深色主题 | 减少局部颜色失真并保留用户偏好 |
| 品牌资产 | 旧 PNG/ICO 与页面品牌呈现不统一 | 使用用户提供的四套 SVG；icon 用于通用项目身份，完整 Logo 限定于关联场景 | 保持矢量清晰度、主题对比度与品牌边界 |

## 响应式规则

### 桌面：大于 1100 px

- 默认显示完整侧栏、顶栏与历史页签；
- 多列概览、并排状态卡和完整表格信息密度；
- 固定操作列用于高效管理长表格。

### 平板：768–1100 px

- 首次进入默认收起侧栏，用户可手动展开；
- 与桌面使用相同的路由、页签、操作和弹窗，不裁剪功能；
- 概览和 Server Control 卡片按可用宽度减少列数；
- 超宽表格不固定操作列，避免覆盖主要内容。

### 手机：小于 768 px

- 侧栏改为带遮罩的抽屉，仍包含当前权限下的全部功能；
- 底部导航按角色提供三个高频入口和“更多”，不是权限替代品；
- 筛选表单单列排列，操作按钮自动换行；
- 表格保留全部字段与操作，通过触控横向滚动访问；
- 弹窗使用接近全屏的宽度，表单标签置顶，并适配刘海和底部安全区；
- Server Control 页签可横向滚动，工具栏、表单和执行按钮按列重排。

## 企业管理员权限

v3.0.0 使用三层角色：

| 角色 | 定位 | 可见范围 |
| --- | --- | --- |
| `user` | 普通用户 | 自己的设备、个人/获共享地址簿和个人记录 |
| `admin` | 范围管理员 | 超管分配的用户组、用户、公共地址簿和 ID 设备四类资源的并集 |
| `super_admin` | 超级管理员 | 原管理员的完整全局能力，并负责角色和范围授权 |

范围管理员的用户组授权会包含组内普通用户及其设备；指定用户授权会包含该用户的设备；指定 ID 设备用于补充单台设备；公共地址簿始终显式授权，不会因管理了其所有者而自动继承，个人地址簿也不会被继承。范围管理员可创建普通用户到已管理用户组，编辑、启停、重置密码和撤销会话，可维护已授权公共地址簿的条目、标签和分享规则；分享目标只能是其管理的用户或用户组。

角色变更、管理员授权、用户删除、用户组和公共地址簿的创建/删除、全局登录与审计记录、OAuth、设备组、Server Control 和全局设置只允许超级管理员。混合范围的批量设备操作采用全有或全无校验，不会跳过越权条目。后端对列表和对象操作独立校验，前端隐藏按钮只用于减少误操作，不作为安全边界。

授权变更会原子替换四类范围、递增目标管理员的 `auth_version` 并撤销其现有会话；授权变更和越权拒绝写入管理审计。删除用户、用户组、设备或公共地址簿时同步清理失效授权。

后续扩展权限点时继续保持“后端权限决定路由和动作、布局只消费权限结果”的边界，可在现有角色与资源范围之上增加动作级策略，而无需重写响应式布局。

## 验收基线

- `npm run lint` 通过前端来源与安全策略检查；
- `npm test` 通过类型化 Server Control、Markdown 清洗、外部弹窗隔离和 Web Client 授权等测试；
- `npm run build` 在固定 Node/npm 版本下成功；
- `go test ./...` 覆盖旧管理员迁移、范围并集、默认拒绝、混合批量拒绝、会话撤销和路由分层；
- 发布前分别在 1440 px 桌面、834 px 平板、390 px 手机和深色模式完成截图与触控巡检；
- 键盘可聚焦导航、主题、语言、账户、认证和主要操作按钮；
- 在手机上验证筛选、分页、横向表格、操作列、弹窗提交与 Server Control 只读流程均可到达。
